============================================================
4. PROTOTYPE - FEATURES BUILT
============================================================
AUTH & ROLES
- Sign up / sign in, three roles (student, facility manager,
  admin), role-based redirects, profile auto-created from
  auth metadata (works with email confirmation on or off).
- Temporary one-tap demo login buttons (Student/Manager/Admin)
  on the login page - marked TEMPORARY, remove before final.

STUDENT
- Guided flow: venue -> facility -> time.
- Venue and facility cards with isometric 2.5D artwork and a
  live "in use / available now" indicator.
- Time-first booking validated against per-facility rules
  (min/max duration, operating hours, advance window,
  capacity); AI-recommended alternatives shown on conflict.
- Equipment requests with live inventory checking.
- "Popular times" chart per facility (busyness by weekday +
  hour from booking history, Google-Maps style, LIVE label).
- My bookings: cancel (with notice rule), self check-in
  around booking time.
- AI chatbot (availability + rules Q&A, grounded on live data).

FACILITY MANAGER (scoped to assigned facilities only)
- Approval queue for their facilities' pending requests.
- Today & upcoming list with attendance tracking
  (mark attended / no-show).
- Equipment inventory editor for their facility categories.
- Lost & found register (log items, track claim status).

ADMIN (organised into tabs: Overview / Analytics / Facilities
/ Approvals / Equipment / Records)
- Facility CRUD with free-form categories and full rule
  configuration (hours, min/max duration, advance, cancel
  notice, auto-approve, capacity).
- Multi-manager assignment per facility.
- Approvals for facilities with no assigned manager.
- Equipment inventory override.
- Analytics: KPIs (total, approval rate, no-show rate,
  avg group size, busiest facility) + charts (bookings over
  time, peak hours, most-booked facilities, status breakdown).
- Records: full activity log (audit trail) with filters + search.

AI
- Recommendation engine (src/lib/recommend.ts): weighted slot
  scoring S = w1*T + w2*C + w3*U (eq. 3.1) - time preference,
  capacity fit, off-peak; deterministic and explainable.
- Adaptive weight learning: weights adjust per user from
  accepted suggestions (online learning), stored in profiles.
- Chatbot (src/app/api/chat/route.ts): intent extraction ->
  RLS-scoped Supabase query -> grounded phrasing; refuses
  off-topic questions; provider-agnostic.

SYSTEM-WIDE
- In-app notifications: header bell + unread badge, driven by
  database triggers (student notified on approve/reject;
  managers/admins on new requests); polls every 30s.
- Activity log: database triggers record every booking,
  approval, facility change, manager assignment, equipment
  edit, lost-and-found action, and signup.
- Professional UI: "Campus Reserve" brand, crimson theme,
  serif display headings, shared app shell, animated landing
  and login pages, tabbed admin.

5. DATABASE MIGRATIONS (run in order in Supabase SQL Editor)
============================================================
Single combined file: supabase/setup-all.sql
Individual files, in order:
  1. setup-full.sql           base schema, RLS, seed, no-overlap
                              conflict constraint
  2. upgrade-equipment.sql    venues, min duration, equipment
  3. upgrade-admin.sql        free-form categories, multi-manager,
                              scoped permissions
  4. upgrade-lost-found.sql   lost & found register
  5. upgrade-activity-log.sql audit trail via triggers
  6. upgrade-notifications.sql notifications via triggers
  7. upgrade-checkin.sql      check-in / no-show columns

Tables: profiles, facilities, facility_rules, reservations,
facility_managers, equipment, reservation_equipment,
lost_and_found, activity_log, notifications.
Conflict prevention: PostgreSQL exclusion constraint
(no overlapping pending/approved bookings per facility).
Access control: row level security throughout, scoped to
role and facility assignment.
